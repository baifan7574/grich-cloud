**GRICH 项目：创始人（Michael Bai）指挥官清单**

**第一阶段：基础设施（地基工程）**

**目标：** 让网站在 Cloudflare 上跑通，不再报 500 错误。

* [ ] **OpenNext 迁移：** 确认是否已放弃过时的 next-on-pages，改用 **OpenNext + Cloudflare Workers** 架构。
* [ ] **动态路由测试：** 随机访问 xxx.dev/compliance/Nike，页面是否能显示出骨架（哪怕没有数据），而不是报错。
* [ ] **老域名解析：** 确认老域名的 DNS 是否已正确指向 Cloudflare，并继承了历史权重。

**第二阶段：种子引擎（采矿工程 - 脚本 1）**

**目标：** 让你的老域名下自动长出几千个品牌页面。

* [ ] **CourtListener API 对接：** 脚本能否成功从法院调取原始案件 JSON 数据。
* [ ] **品牌提取逻辑：** AI 脚本能否从“Nike vs. X”中准确提取出 Nike 并存入 **Supabase**。
* [ ] **自动页面生成：** 数据库里每增加一个品牌，前端网站是否会自动生成对应的新页面。

**第三阶段：报告引擎（加工工程 - 脚本 2）**

**目标：** 将流量变现，生成值 $9.9 的专业 PDF。

* [ ] **DeepSeek API 接入：** AI 是否能读懂案件卷宗并按照“Michael Bai 模版”撰写报告。
* [ ] **PDF 生成测试：** 系统能否自动把 AI 的文字转换成精美的、带防伪标的 PDF 文件。
* [ ] **支付跳转确认：** 点击“Unlock”按钮后，能否正确跳转到收款页面。

**🛠️ 只有两个脚本，分工非常明确**

为了不让你晕，你只需要记住这两个“员工”的职责：

| **脚本名称** | **它的外号** | **它的核心任务** | **对应的 API** |
| --- | --- | --- | --- |
| **脚本 1：种子引擎** | **“采矿工”** | 每天去法院抓新品牌名，塞进数据库，**制造几千个网页截流**。 | CourtListener API |
| **脚本 2：报告引擎** | **“加工师傅”** | 用户付钱后，把案子写成 PDF 报告，**完成变现**。 | DeepSeek API |
