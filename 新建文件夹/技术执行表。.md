**2. 数据库设计 (Supabase Schema)**

**A. lawsuits 表 (核心情报库)**

* id: UUID (Primary Key)
* case\_number: String (案号，如 2:24-cv-00123)
* brand\_name: String (品牌名，用于动态路由生成 URL)
* plaintiff: String (原告/律所，如 GBC, Keith)
* court: String (管辖法院)
* filed\_date: Date (起诉日期)
* status: Enum (密封/解封/冻结中)
* risk\_score: Integer (0-100 风险指数)
* raw\_data\_url: String (CourtListener 原始 JSON 链接)

**B. reports 表 (交付物管理)**

* id: UUID
* user\_id: UUID
* case\_id: UUID
* payment\_status: Boolean (是否已支付)
* pdf\_url: String (R2 存储桶中的文件地址)
* ai\_summary: Text (AI 生成的内容摘要)

**3. 核心功能模块实现逻辑**

**模块一：种子引擎 (Seed Engine - 脚本 1)**

1. **抓取循环**：通过 Python/Node.js 定时请求 CourtListener API。
2. **清洗逻辑**：使用正则表达式从诉讼标题中提取 brand\_name，剔除 "Inc.", "LLC" 等后缀。
3. **入库校验**：检查案号是否存在，若为新案，计算初步风险分并存入 lawsuits 表。

**模块二：pSEO 动态路由引擎 (Frontend Engine)**

1. **动态路径**：配置 /compliance/[brand] 路由。
2. **数据提取**：在边缘端 (Edge Runtime) 直接调用 Supabase，根据 URL 中的 brand 查询数据库。
3. **专家注入 (E-E-A-T)**：
   * 页面底部必须包含 AuthorProfile 组件，自动注入 Michael Bai 的 16 年背景介绍（法律、心理、电商讲师） [cite: 2025-12-26, 2025-12-28]。
   * 每个报告摘要页必须包含“Michael 的应对建议”模块 [cite: 2025-12-26]。

**模块三：自动报告引擎 (Report Engine - 脚本 2)**

1. **触发机制**：接收支付成功 Webhook。
2. **AI 分析**：
   * 输入：从 CourtListener 下载的 PDF 卷宗文本 + Michael 的专家分析框架。
   * 调用：DeepSeek API 生成结构化 Markdown 报告 [cite: 2025-12-18]。
3. **文件交付**：将 Markdown 转换为 PDF，存入 Cloudflare R2，并通过 SendGrid 自动发送下载链接给用户。

**4. 环境变量与安全配置**

必须在 Cloudflare Pages 的 Dashboard 中配置以下变量：

* SUPABASE\_URL: 数据库连接地址
* SUPABASE\_ANON\_KEY: 数据库访问 Key
* DEEPSEEK\_API\_KEY: AI 接口 Key
* COURTLISTENER\_API\_KEY: 法律数据接口 Key
* NEXT\_PUBLIC\_SITE\_URL: https://grich.cloud
