即便商业模式逻辑通顺，GRICH 项目依然面临以下 5 个足以致命的坑。

**1. 谷歌的“内容农场”死刑 (SEO 风险)**

这是最直接的威胁。虽然我们用的是真实数据，但如果你生成 10,000 个网页，而每个页面的结构 90% 都是重复的（只有品牌名和案号在变），谷歌的算法会将其判定为 **“Scaled Content Abuse”（规模化内容滥用）**。

* **后果：** 你的网站会瞬间从搜索结果中消失，也就是所谓的“被封号”。
* **避坑指南：** 绝对不能只靠 AI 拼凑。你需要增加“非 AI”部分，比如真实的律所评价、历史和解案例数据库，以及 Michael Bai 作为资深律师的专业点评模块，以此向谷歌证明你不是“搬运工”，而是“加工厂”。

**2. UPL 法律红线 (合规性风险)**

作为一个律师，你一定知道 **UPL (Unauthorized Practice of Law - 无证法律执业)**。

* **坑在哪里：** 如果你的 AI 报告里说：“你应该支付 $3,000 给律所进行和解”，这在法律上可能被视为\*\*“法律建议”\*\*而非“法律信息”。在美国，给美国人提供法律建议必须有当地执业资格。
* **避坑指南：** 报告必须定位为 **“数据分析报告”**。每一页都要用显眼的字体标注：*“本报告仅基于历史数据分析，不构成法律建议。如需法律行动，请咨询美国执业律师。”*

**3. 支付账户的“突然暴毙” (财务风险)**

这是很多数字游民最容易栽跟头的地方。

* **坑在哪里：** 卖家在极度焦虑下付了 $9.9，如果他们发现你的报告没能帮他们解冻账户，或者他们觉得内容不够多，由于他们正处于资金链断裂边缘，\*\*投诉率和退款率（Chargeback）\*\*会非常高。
* **后果：** 一旦 Stripe 或 PayPal 的拒付率超过 1%，你的账户会被永久封禁，美金取不出来。
* **避坑指南：** 支付前必须有极度清晰的“内容预览”，明确告诉用户报告包含什么、不包含什么。

**4. 数据源的“限流与收费” (技术风险)**

你目前依赖 CourtListener 等公开 API。

* 坑在哪里： 1. 限流： 如果你的抓取脚本没写好，疯狂请求，你的 IP 会被封。

2. 收费： 如果 CourtListener 突然改变政策，对 API 接口开始收取高额费用，你的利润空间（Profit）会被瞬间吃掉。

3. 密封件： 很多 SAD 案件的“被告名单”是 Sealed（密封） 的，API 根本抓不到。

* **避坑指南：** 建立自己的二级数据库，抓下来的数据要存好（Supabase），减少对外部 API 的实时依赖。

**5. AI 的“一本正经胡说八道” (产品风险)**

DeepSeek 等大模型虽然聪明，但它在处理极其枯燥的法律文书时，偶尔会产生 **Hallucination（幻觉）**。

* **坑在哪里：** 如果 AI 把 A 律所的行为特征安在了 B 律所头上，或者把赔偿金单位看错了（比如 $3,000 看成了 $30,000），这会导致你的报告信誉彻底破产。
* **避坑指南：** 建立一个“规则过滤器”。对于核心数据（金额、律所、案号），由 Python 脚本进行硬代码匹配，只让 AI 处理文字总结部分。
